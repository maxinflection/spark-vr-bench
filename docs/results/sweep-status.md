## Methodology notes

- All scores are `pass_rate` at full bench size (`n` shown). Greedy decoding (temperature=0), single-stream.
- **HumanEval+** — `humaneval_plus_chat` (lm-evaluation-harness, 164 problems), greedy pass@1.
- **IFEval** — `prompt_level_strict_acc` (lm-evaluation-harness, 541 prompts). Vendor model-card IFEval numbers are NOT lm-eval prompt_level_strict — do not chase them. Visible `<think>` blocks can *lower* strict-accuracy here, which is part of why thinking-on/off is shown paired.
- **BigCodeBench-Hard** — `hard` subset (148 tasks) via the bigcodebench docker evaluator, calibrated pass@1. Truncation is the runner's `[bcb-none-filter]` null-content rate (`bd <ISSUE>`).
- **CyberGym** (Pool A) — deterministic PoC execution (no LLM judge); 10-task subset; OpenHands CodeActAgent, max_iter=100.
- **SEC-bench** (Pool A) — differential sanitizer on patch; 11-task subset; smolagents. (s) = stock @ max_steps=30 (canonical); (p) = `bd <ISSUE>`+`bd <ISSUE>` patched @ max_steps=50. (s) stays canonical for cross-harness comparability.
- **CVE-Bench** (Pool A) — agentic web RCE/injection; 40 dockerized CVEs via Inspect AI, max_messages=30. Project-canonical condition is thinking-off.
- **Context budget** — rental specs floor `max_model_len` at 128K, target 256K. Pool B reasoning responses (`<think>`) and SEC-bench `poc-san` first messages can exceed 8K/16K — the truncation diagnostic exists because the 16K thinking budget is sometimes binding (`bd <ISSUE>`/`bd 6z4`).
- **Thinking-mode realism** — every reasoning-capable model × bench is measured in both modes where feasible; neither is forced into a single headline when the modes diverge and one is truncation-contaminated. Canonical = the benchmark author's intended config (see `docs/research/benchmark-canonical-protocols.md`), which is a *lens*, not a winner.
